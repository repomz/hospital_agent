# Формат протокола после обработки

- `conclusion`: только явно выделенное заключение («Заключение:» или «В ходе исследования выявлено:»). Если раздела нет, пустая строка; описание не подставляется вместо него.
- `description`: краткий ход операции до заключения. Сохраняются вмешательства, сосуды, сторона, устройства, размеры, численные результаты и осложнения. Типовые предложения об удалении инструментов и наложении повязки сокращаются; сообщения об осложнениях не удаляются по этому правилу.
- `department`: определяется по номеру карты; это явное поле Study API и базы данных, используемое интерфейсом.
- `options`: пустая строка либо разделённые запятыми метки `ivus`, `vabk`, `ekmo`. Они отражают дополнительные методы и не подменяют основной `study_type`.
- `study_type`: определяется по названию с проверкой результата вмешательства в описании. Для постоянных ЭКС — `ЭКС 2к`/`ЭКС 1к`, для временных — `ВЭКС`. Стент-ретривер сам по себе не означает выполненное стентирование.
- `birth_date`: дата из документа, не расчёт по возрасту.
- `room`: 1 или 2 из «Операционная №…». При отсутствии или противоречивых номерах поле не выдумывается.
- `recommendation`: только рекомендация с «в плановом порядке».

ВАБК/ЭКМО при КАГ, стентировании или БАП попадают в `options`, основной тип сохраняет вмешательство. Название «Установка внутриаортального ВАБК» сокращается до «ВАБК». Для периферических артериальных ангиографий и эмболизаций тип дополнительно указывает «периферии».

Не исправляем догадкой несоответствия между стороной/сосудом в названии и описании. Примеры сохраняют такие ошибки исходника. Это детерминированное сокращение, а не медицинская редактура или восстановление отсутствующих фактов.

В описании и заключении знаки `+` и `=` удаляются без замены словами. Сегменты записываются без пробелов: `М1-М2`. Сведения о времени рентгеноскопии и лучевой нагрузке не включаются. Пустые/нечитаемые/неполные протоколы сопровождаются WARNING с полным путём. Временные файлы Word `~$…` не считаются протоколами. Предупреждения поступают на сервер с очередной штатной часовой отправкой логов.

ВМП/ОМС автоматически назначается только операциям текущего года по времени Томска. Архивные записи без исходной классификации остаются без неё.

## Проверка без отправки на сервер

```sh
python scripts/preview_protocol_payloads.py /path/to/protocols
```

Скрипт читает DOCX, выводит статистику и примеры с заменённым ФИО; сетевых запросов и записи в базу нет. Число обработанных файлов не равно числу уникальных операций: в исходной директории есть копии.

Контрольная выборка: январь–июль 2026, 1793 файла; 14 временных файлов Word пропущены, 1772 обработаны, 7 не распознаны как полноценный протокол. У 97 документов нет явного заключения, в 53 обнаружено ВСУЗИ.

## Совместимость и выкладка

Приоритет коронарных вмешательств: выполненное стентирование (включая ДА), затем выполненная БАП, иначе КАГ. Упоминание попытки или ранее установленного стента не подтверждает выполненное стентирование. Церебральные ТА/ТЭ имеют приоритет над сопутствующими периферическими вмешательствами: тип `инсульт`. ОСА относится к `стент_вса`, позвоночная артерия — к `стент_па`.

Повторная проверка двух папок за январь–июль: 1766 уникальных операций из 1772 обработанных файлов, 21 встречающийся основной тип; ВСУЗИ — дополнительный признак у 50 уникальных операций. Полные обезличенные примеры и распределение типов находятся в `protocol_payload_examples.json`. Это результат автоматических правил, не независимая медицинская верификация исходников.

Скрипт многолетней статистики использует тот же классификатор и отправляет schema_version 3: ВСУЗИ учитывается поверх основного типа, а не вместо него и не увеличивает итог. Новый сервер принимает версии 2 и 3, сохраняя прежние правила подсчёта для старых документов версии 2. Сначала обновить сервер, затем запускать новый скрипт.

Сначала требуется обновить сервер с миграцией дополнительного поля `description` и фронтенд, затем агента. Новый JSON отправляет `conclusion` вместо `descr_operation`. Сервер продолжает принимать старое имя от прежних агентов; физическая колонка заключения пока сохраняет прежнее имя, чтобы не разрушить старые данные и SQL-запросы. Ответ API использует `conclusion`.

Этот прогон не изменяет существующие записи в базе. Массовую повторную загрузку нельзя выполнять вслепую: прежняя идентификация использует в том числе название операции, которое теперь сокращается иначе. Для обновления исторических записей требуется отдельная проверка сопоставления и исключение дублей.
