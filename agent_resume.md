## `send_study_to_yandex` - переименовывем в "get_xa" или "get_ct" соответсвенно исследованию

Пример:

```json
{
  "command": "get_xa",
  "study_uid": "1.2.840..."
}
```

На больничном компьютере происходит следующее:

1. Загружается PACS-конфигурация из `config.json`.
2. В системной временной папке Windows создаётся каталог примерно такого вида:

```text
%TEMP%\hospital-agent-<request_id>-xxxxxx
```

3. Агент подключается к больничному PACS.
4. Через DICOM C-FIND получает фамилию пациента, дату исследования и ожидаемое количество файлов. // так как в этой команде уже известен "study_uid": "1.2.840..." то можно сразу переходить к c-get по "study_uid": "1.2.840..."! find здесь делать бессмысленно
5. Через C-GET скачивает исследование.
6. Каждый instance сохраняется локально как:

```text
<SOPInstanceUID>.dcm
```

7. Проверяется соединение с Yandex Object Storage.
8. Все скачанные файлы загружаются в Yandex в папку: 

```text
Фамилия_ДД.ММ.ГГГГ
```

9. После завершения команды временная локальная папка полностью удаляется
10. Backend получает статистику: число файлов, байты, длительность, ожидаемое число instance, папку Yandex и список не загруженных файлов.

Важные особенности:

- настройки Yandex берутся из переменных окружения;
- для каждого файла сейчас предусмотрено 3 попытки с паузой 5 секунд;
- уже загруженные в Yandex файлы при частичной ошибке не удаляются; // при ошибке в "status" в user_requests должен соответсвующий ответ
- если отдельные файлы не загрузились, они попадают в `failed_files`, но вся команда всё равно может завершиться с `ok=true`; // такого быть не должно
- путь `download_dir` возвращается backend, но к этому моменту папка уже удалена; // не нужно вовсе
- сама команда не обновляет `dicom_link` исследования — она только возвращает результат через callback. // dicom_link должен быть заполнен при удачной отправке CT или XA исследования 
- когда бекенд получает dicom_link то значит ссылка на dicom в yandex уже есть и далее бекенд должен скопировать эти файлы в remote pacs(mapdr) по http например скриптом python логику которого можно взять из проекта больничного агента


## создаем "find_xa" - найти XA ангиографию в локальном PACS или "find_ct" - найти найти CT в локальном PACS по фамилии пациента - в ответ приходит фио дата и название исследования и его "study_uid" (от одного или нескольких опер при наличии или вдруг были однофамильцы), этот список будет анализирован на фронте и из них будет выбран один определенный для скачивания уже самого исследования используя его "study_uid" и команду "get_xa" или "get_ct"

Пример:

```json
{
  "command": "get_xa" // из названия команды автоматически определяется modality для find
  "period": "" // today, yesterday, week, month, или за определенную дату
}
```
